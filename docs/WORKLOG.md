# 작업 기록

맥(개발)과 병원 PC(씨차트, Windows)를 오가며 이어서 작업하기 위한 인수인계 문서다.
작업을 마칠 때마다 **현재 상태**와 **다음 할 일**을 고치고 **작업 기록**에 한 줄을 더한다.
사용법은 [README.md](../README.md), 작업 규칙은 [CLAUDE.md](../CLAUDE.md).

**되어 있는 것** (자세한 사용법은 README)

- 녹음 → whisper.cpp 로컬 전사 → 말한 사람 표시(등록한 의사 목소리) → 요약(Claude Code CLI 또는 로컬 llama.cpp) → 진료 기록 저장
  (무음을 줄인 FLAC·전사문·요약·환자 이름, 찾기, 날짜별·환자별 묶기, 삭제)
- 간단 화면(스페이스바 녹음)과 개발자 보기, 자동 진료 나누기(무음 90초·'들어오세요'·끝인사)
- 의사 목소리 등록 + 따라 읽기 학습(11개 과 × 12문장) + 의사별 딕션 사전(용어 힌트·교정, 전사문에서 고치면 배우기), 끼어든 말 나누기
- macOS·Windows·Linux 설치 스크립트, '설치' 창, 자동 업데이트(CI 통과 버전만)
- 녹음 버튼: USB 버튼(전역 단축키, 기본 F13)으로 씨차트를 보면서 녹음 시작·종료, 구석 표시창과 소리, 요약이 끝나면 자동 복사
- 씨차트 연결(Windows): 점검에서 환자 이름 자리와 진료 기록 칸을 배워 저장 → 녹음 시작과 20초 뒤에 환자 이름을 읽어 진료에 붙임 →
  버튼으로 녹음한 진료의 요약을, 읽은 이름이 모두 같고 씨차트에 아직 그 환자가 열려 있을 때만 진료 기록 칸 끝에 덧붙임
  (진료마다 한 번, 저장은 의사가 직접)

**확인하지 못한 것**

- **실제 씨차트**: 가짜 진료 차트 창(Windows CI)으로만 확인했다. 씨차트가 화면 읽기로 이름을 내보내는지, 관리자 권한으로 도는지,
  진료 기록 칸이 어떤 종류(Edit·RichEdit·메모·그 밖)인지 모른다.
- 실제 사람 목소리로 말한 사람 표시·끼어든 말 나누기 (가상 음성으로만 확인. 판정 기준 0.55 는 조정이 필요할 수 있다)
- 병원 PC 사양: GPU 없는 CI 컴퓨터에서는 실시간 전사가 녹음보다 1분 넘게 늦었다. 병원 PC 가 CPU 만이면 확인할 것
- 실제 USB 버튼 장치 (키 누르기는 Windows CI 에서 가짜 입력으로만)
- 로컬 요약 모델의 실제 llama-server 실행 (가짜 서버로만, 실제 실행은 사용자 허락이 필요)

## 다음 할 일

### 1. 병원 PC 에서 씨차트 연결 점검 (사용자)

1. 앱을 최신으로: 위쪽 `새 버전` → `다시 열어 적용` (설치 전이면 README [설치 (새 컴퓨터)](../README.md#설치-새-컴퓨터)).
2. `설정 → 씨차트 → 씨차트 연결 점검…`
   - 씨차트에서 환자 한 명을 열고 그 이름으로 찾기 → 다른 환자로 바꿔 한 번 더 → "같은 자리 N곳에서 이름이 읽힙니다 … 저장했습니다" 가 나오면 이름 자리 완료
   - 진료 기록 칸에 `@@@@` 를 적고 `칸 찾기` → `칸 정함` 이 나오면 `@@@@` 를 지운다
3. 테스트용 환자 차트에서 가상 대화로 확인: 녹음 버튼 → 말하기 → 녹음 버튼 → 요약이 그 칸 끝에 붙는지,
   녹음 중에 다른 환자를 열면 넣지 않고 복사만 하는지
4. 안 되면 점검 창의 `결과 저장…` 파일(`씨차트_연결_점검_*.txt`, 이름은 `[환자 이름]` 으로 가려짐)을 Claude 에게 준다

### 3. 사용자가 정하기로 한 것 (요청 전에는 만들지 않는다)

- 실제 차트에 필요한 칸(요약 형식): 사용자가 알려 주기로 했다. 받으면 요약 형식을 그 칸에 맞춘다.
- 제안만 해 둔 것: 녹음 동의 안내문 초안, 진료 기록 암호화, "뻔히 잘못 들린 말만 고치고 원문 → 고친 말을 보이는" 요약 모드.
- 의사별 Whisper 미세 조정: 만들지 않았다 (진료 녹음이 쌓이므로 재료는 있다).
- 진료 기록 자동 삭제 기간: 없다. 요청 전에는 만들지 않는다.
- (개발 Mac) 한글 입력 버그(고침) 때문에 끝 글자가 빠진 채 등록된 의사 목소리 이름이 하나 있다. 사용자가 원할 때 앱을 닫고 바꾼다.

## 주요 결정과 이유

- **요약은 Claude Code CLI** (`summarizer.py`): `--safe-mode`(CLAUDE.md·hooks·플러그인·MCP 를 끔), `--tools ""`, `--no-session-persistence`,
  임시 작업 폴더, 전사문은 stdin. 그래서 이 repo 의 CLAUDE.md 는 요약에 섞이지 않는다. Ollama 는 앱에서 뺐고 `scripts/bench_ollama.py` 는 비교 실험용이다.
- **로컬 요약**은 llama.cpp `llama-server` + Qwen3 GGUF (사용자가 'Claude 또는 로컬' 선택을 원했다). 설정 `summary_engine` 이 비어 있으면 '설치' 창이 한 번 묻는다.
- **요약 내용**: 환자가 말한 세부(부위·색·횟수·밤에 깬 횟수 등)를 한 항목에 사실 하나씩, 환자 말 그대로 남긴다.
  의사가 판단과 나중의 근거("그때 그렇게 말씀하셨다")로 중요하게 본다.
- **전사**: `whisper-cli -ml 1 -sow` 로 낱말 단위 시각을 받고, 더 짧은 VAD(300 ms)로 구절을 묶은 뒤 문장 끝·1초 쉼·말한 사람이 바뀔 때 줄을 나눈다.
  `-ojf` 의 토큰 시각은 VAD 로 줄인 시각이라 쓰지 않는다.
- **딕션 힌트**는 "용어들. 기본 프롬프트" 꼴이어야 한다. 쉼표로 이으면 Whisper 가 두 사람 말을 한 줄로 합쳤다.
- **말한 사람**: sherpa-onnx 3D-Speaker CAM++ 로 등록한 의사 목소리와 비교한다 (기준 0.55).
- **진료 기록**: 원래 "내보낼 때만 저장" 이었지만 2026-11-12 사용자 요청으로 저장한다. 1.2초 넘는 쉼을 1.2초로 줄인 16 kHz FLAC + SQLite,
  폴더 700·파일 600, secure_delete. 녹음 파일 이름은 번호만 쓴다 (환자 이름이 탐색기·백업에 보이지 않게).
- **자동 업데이트**: CI 를 통과한 커밋만, 앱을 열 때 적용, 새 버전이 창을 못 띄우면 되돌린다. 고친 파일이 있거나 main 이 아니면 건드리지 않는다.
- **녹음 버튼**: USB 버튼·풋페달이 보내게 정한 키(기본 F13, 보통 키보드에 없는 키)를 전역 단축키로 받는다. Windows `RegisterHotKey`, macOS Carbon.
- **씨차트**: 공개 API 가 없다. 사용자의 현장 점검 보고를 기다리지 않고 '현장에서 배우는' 방식으로 만들었다. 점검이 두 환자에서 같은 자리를 찾아
  가린 모양으로 저장하고, 표시 글자 `@@@@` 로 진료 기록 칸을 찾는다. 이름은 녹음 시작과 20초 뒤에 읽어 모두 같아야 넣고, 진료마다 한 번만 넣는다.
- **CI**: macOS 는 모델 없는 테스트만 돌린다 (GitHub Mac 가상 컴퓨터는 GPU 가 없어 90분을 넘긴다, 사용자 동의). macOS 전체 테스트는 개발 Mac 에서 GPU 로.
  Windows·Linux 종료 중 비정상 종료는 Qt 창이 인터프리터 종료까지 남아서였다 → `app.close_qt()` 와 CI 종료 점검.
